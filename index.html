02 / OUT IN THE OPEN

The same discipline applied to the project everything else runs on top of.

KEP-6312 · kubernetes/enhancements

Relaxed validation for HostAliases hostnames.

Authored a Kubernetes Enhancement Proposal to sig-network, relaxing hostAliases[].hostnames validation behind a feature gate to accept trailing-dot FQDN notation, standard Unix hosts-file syntax that kube-apiserver currently rejects outright with no workaround.

The proposal was shaped directly by a previous KEP's regression: a DNS validation fix that worked under glibc but silently broke resolution under musl libc (Alpine). The test plan here requires verifying actual hostname resolution inside both glibc and musl containers, not just confirming the API server accepts the object.

Verify real behavior, not surface-level success.

03 / HOW I THINK

Own the whole path.

From design to production traffic, and whoever's on call when it breaks.

01

Verify real behavior.

An API accepting an object isn't the same as the system working. Test what actually happens at runtime, across the environments that matter.

02

Change should be reversible.

Feature-gated, additive rollouts. Nothing ships in a way that can't be dialed back without taking workloads down with it.

03

Isolation is architecture, not policy.

Boundaries that matter get built into the infrastructure itself, not enforced by convention or a note in a runbook.
